# HOME 복귀를 제외한 pick-and-place 보조 데이터

## 구성

원본은 인형 499개와 종이컵 250개, 합계 **749개**다. 750개로 맞추기 위한 복제는 하지 않았다.

출력은 `robot_datasets/derived/pickplace_nohome_v1/` 아래에 있다.

| 대상 | LeRobot 데이터 경로 | 학습 / 검증 에피소드 | 보존 프레임 | 제거 프레임 |
|---|---|---|---|---|
| 인형 | `doll/dataset` | 449 / 50 | 235,258 | 56,611 |
| 종이컵 | `cup/dataset` | 200 / 50 | 112,424 | 39,707 |

합계 347,682프레임을 보존하고 HOME 후반부 96,318프레임을 제외했다.

각 대상의 `split.json`은 기존 분할을 보존한다. 원본 데이터와 기존 sorting 모델은 수정하지 않는다. 이 작업은 데이터 생성이며, 새 학습을 실행하지 않는다.

## 잘라낸 범위

접근 → 파지 → 운반 → 상자에 놓기 → 놓은 물체에서 그리퍼가 빠져나오는 데 필요한 짧은 여유 동작을 남긴다. 이후 HOME으로 돌아가 정지하는 구간은 학습 범위에서 제외한다.

모든 에피소드의 후보 경계 전후 SIDE 영상과 경계의 TOP 영상을 검토했다. 인형은 그리퍼 개방 시점에도 물체를 계속 들고 있는 경우가 있어, 내려놓은 시점까지 경계를 연장했다. 영상의 물체 위치 비교로 보정하고 예외는 스냅샷을 직접 확인했다. 경계별 결정은 `approved_boundaries.json` 및 각 대상의 `derivation.json`에 기록한다.

영상은 원본 파일의 하드링크를 재사용한다. 따라서 파일 자체에는 원본 후반 영상이 남아 있지만, 새 데이터의 프레임 수·에피소드 경계·영상 참조 시간에는 잘라낸 앞부분만 포함된다. 학습에 쓰는 action/state 테이블에서는 후반부를 실제로 제거했다. 원본 영상이나 링크 파일을 수정하면 양쪽에 영향을 주므로 둘 다 편집하지 않아야 한다.

## 검사 범위와 결과 확인

2026-10-24 검사 결과: **749개 모두 통과**, `ready_for_training: true`. 인형 499회·종이컵 250회의 실제 RGB/action 로더 경계 조회가 성공했다.

최종 결과는 `BUILD_STATUS.json`과 `validation_report.json`을 기준으로 확인한다. `ready_for_training: true`는 아래 검사를 모두 통과했음을 뜻한다.

- 749개 전체의 에피소드 수, 프레임 수, 인덱스, 타임스탬프, 학습/검증 분할 검사.
- 보존한 모든 action/state 값이 원본 앞부분과 정확히 일치하며 유한값인지 검사.
- 모든 에피소드에서 실제 LeRobot 로더로 TOP/SIDE RGB와 100-step action chunk 조회.
- 잘린 끝을 넘는 action은 같은 에피소드 마지막 값으로 제한되고 `action_is_pad`로 표시되는지 검사.
- 원본 영상과의 파일 동일성, 크기, 수정 시각 및 영상 참조 범위 검사.

이는 구조·로딩·검토한 경계의 검사다. 모든 영상 프레임을 연속 재생하거나 각 시연의 물리적 성공 전체를 판정한 것은 아니므로, 시연 품질까지 절대적으로 오류가 없다는 보증은 아니다.

## 후속 ACT 혼합 학습 시 주의점

정책 입력용 RGB TOP/SIDE, state, action 및 필수 인덱스만 포함한다. depth 등 수집 부가 필드는 원본에 보존되어 있다. sorting에도 같은 입력 스키마를 사용해야 한다.

수치 통계는 보존한 모든 프레임으로 다시 계산했다. RGB 통계는 각 에피소드의 균등한 12프레임에서 픽셀을 표본 추출했다. 기본 전체 통계에는 검증 에피소드도 포함되므로, 실제 학습 정규화는 **train 에피소드 통계만 다시 집계**해야 한다.

이 데이터는 놓기 이후에 종료되는 보조 시연이다. 두 물체 사이의 연결 동작과 두 물체 분류 후 HOME 복귀는 전체 sorting 시연으로 학습해야 한다. 별도 데이터 생성만으로 파지 전용 손실이나 sorting 우선 샘플링이 자동 적용되지는 않는다.

생성 스크립트: `scripts/build_pickplace_nohome.py`. 검사 스크립트: `scripts/validate_pickplace_nohome.py`. 생성기는 기존 출력 폴더 덮어쓰기를 거부한다.
