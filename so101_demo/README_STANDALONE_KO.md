# LeRobot 없이 ACT 추론하는 실험 코드

## 모델 선택

- 인형: `act_doll_basic/checkpoints/047000/pretrained_model`. B200 학습 후
  검증 관측에서 선택했으며, 이 실험의 실물 성공을 사용자가 확인한 기록이 있다.
  정량 성공률과 성공 당시 정확한 실행 리비전은 확인되지 않았다. 이전에 연결한
  100개 시연 기반 `020000`과 서로 다른 모델이다.
- 종이컵: `act_paper_cup_basic_20261021_224407_822254/checkpoints/044000/pretrained_model`.
  50개 검증 에피소드의 손실이 가장 낮은 체크포인트이며 실물 성공률은 미측정이다.

서로 다른 작업이므로 두 모델 사이의 성공률 순위를 매긴 것이 아니다.

2026-11-18: 인형 `047000`을 Jetson TensorRT 엔진으로 교체하고 기존
인형 전용 8프레임 조기 그리퍼 닫기를 비활성화했다. 학습 데이터 2개 관측에서
원본 CPU와 변환 ONNX의 최대 차이는 각각 0.000046, 0.000039, Jetson 엔진과
원본 CPU의 한 관측 차이는 최대 0.000062였다. 카메라 두 대와 관절을 읽는
추론 전용 시험 3회는 성공했으나, 교체 후 실물 파지·방향·성공률은 미검증이다.
기존 020000 실행 중 shoulder_lift stall이 발생했으며 원인은 미확정이다.

## 구성

`standalone_act.py`는 설치된 LeRobot과 PyTorch 없이 두 RGB 영상과 여섯 관절
값을 입력받아 100×6 동작 묶음을 계산한다. 원본 checkpoint의 전처리·후처리
통계를 `model_stats/`에 보관한다. CPU의 ONNX Runtime은 개발 PC/B200 검사용이고,
Nano에서는 별도 변환한 TensorRT 엔진을 사용한다. `local_inference_worker.py`와
`local_inference_client.py`는 Jetson의 시스템 Python 3.6 TensorRT와 기존
Python 3.12 환경을 연결한다. 일시적인 영상 전달은 `/dev/shm`에서 처리한다.

`standalone_act.py` 자체는 **모터에 명령을 보내지 않는다.** `local_act_demo.py`,
`teleoperation.py`, `demo_menu.py`는 Jetson에 준비됐고 `lerobot` 명령이 설치됐다.
사용자는 텔레오퍼레이션 추종과 Q 정상이 동작한다고 확인했다. ACT 실물 동작과
정지는 아직 가상 장치로만 시험했으며 현장 시험은 진행하지 않았다.

## 검증 상태

- B200에서 두 checkpoint를 ONNX로 내보내고 ONNX 구조를 검사했다.
- 두 모델 모두 기존 수집 데이터 2개 시점에서 ONNX CPU 출력과 원본 PyTorch
  CPU 출력의 최대 차이는 약 0.0001 이하. 동일 테스트의 B200 GPU 출력과의
  차이는 더 컸고, 기존 인형 실행기는 FP16을 사용하므로 동일 성공률을 보장하지
  않는다. 표본 2개는 모델 전체 또는 실물 성공률 검증이 아니다.
- Jetson TensorRT용 Python 호출 및 GPU 메모리 입출력은 작은 별도 모형으로
  시험했다. 실제 모델이 아니라 임의 검사용 모형이다.
- ACT와 같은 구조의 영점 가중치 검사 파일은 TensorRT가 읽었으나, 원래 ONNX
  그래프는 입력 603개의 결합 연산에서 엔진 생성에 실패했다. 이를 줄이기 위해
  원본 그래프의 순서가 보존되는 분리→결합을 제거한 후 B200에서 출력을 재비교했다.
  수정된 영점 가중치 검사 파일은 Nano에서 엔진 생성 및 GPU 실행에 성공했고,
  준비 후 2회 실행은 각각 약 402ms, 404ms였다. 이는 실제 모델이 아닌 검사용
  그래프이므로 실제 모델의 속도나 성능을 뜻하지 않는다.
- 5GHz 동글 연결 후 종이컵과 인형 ONNX 파일을 Jetson으로 전송했으며 각각
  SHA-256으로 원본 일치를 확인했다. 종이컵의 실제 TensorRT 엔진은 생성됐고,
  기존 수집 데이터의 한 표본에서 원본 PyTorch CPU 출력과 최대 차이 약
  0.00005를 기록했다. GPU 계산은 첫 실행 약 553ms, 이후 약 404ms였다.
- 인형 실제 TensorRT 엔진도 생성됐고, 기존 수집 데이터의 한 표본에서 원본
  PyTorch CPU 출력과 최대 차이 약 0.00007였다. 이 표본에서 B200 FP16 출력과
  최대 차이는 약 0.179였다. 실제 작업 성공률의 차이는 알 수 없다.
- 두 엔진 모두 실제 카메라 두 대와 현재 Follower 관절 상태를 읽는 시험에서
  각 5회 유한한 100×6 동작을 반환했다. 준비 후 로컬 추론 통신 포함 시간은
  대체로 종이컵 0.46~0.47초, 인형 0.47~0.48초였다. 첫 실행은 더 느렸다.
  이 시험에서는 **모터에 명령을 보내지 않았다.**
- **ACT 실물 로봇 작동, 정지와 성공률은 아직 확인하지 못했다.** 한 장면의 출력
  비교와 정지 상태의 추론 속도만으로 실물 시연이 안전하거나 성공한다고 볼 수 없다.
- 5GHz 동글(`wlan1`, 192.168.25.147)로 B200 연결 경로를 임시 전환한 뒤,
  카메라 2대를 켠 상태에서 JPEG 왕복 60회와 PNG 왕복 10회가 성공했다.
  B200 경로 설정은 재부팅 후 자동 유지되지 않는다. 독립 실행 추론은 B200을
  사용하지 않는다.
- 종이컵 실물 제어 시도에서 `제어 주기가 너무 느려 정지합니다`가 발생했다.
  정지 후 Follower는 홈에서 벗어난 자세를 유지했다. 모터 명령을 보내지 않은
  진단 360회에서 기존 영상 표시 구간은 최대 236.7ms, 전체 루프는 최대
  239.3ms였다. 영상 창을 별도 프로세스로 분리한 후 동일한 읽기 전용 진단에서
  영상 표시 구간 최대 18.1ms, 전체 루프 최대 34.3ms였다. 이 값에는 실제
  모터 쓰기가 포함되지 않으며, 수정 후 실물 추종과 Q 정지는 미검증이다.

## 엔진 준비 후 오프라인 사용 예

아래 명령은 `cup.engine`, 해당 엔진 해시를 포함한 `cup_engine_stats.json`,
입력 `observation.npz`가 모두 준비된 **이후에만** 사용할 수 있다. 입력 파일
키는 `state`(6개), `top_bgr`, `side_bgr`(각 480×640×3 uint8)이다.
출력은 관절 제한을 적용하지 않은 원시 예측이므로 모터에 직접 보내지 않는다.

```bash
/usr/bin/python3 standalone_act.py \
  --backend tensorrt --model cup.engine --stats cup_engine_stats.json \
  --input observation.npz --output prediction.npz
```
