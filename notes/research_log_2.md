## 2026-10-01 : 본 데이터 수집 환경 구성

SO-101 Leader(`COM4`)–Follower(`COM3`) 텔레오퍼레이션과 기존 보정값을 사용한다. 카메라는 RealSense D405 TOP RGB·depth와 Webcam SIDE RGB이며, 640 × 480, 목표 수집 속도 30 FPS로 구성했다. `collection/수집 실행` 바로가기에서 인형·종이컵 집기, 인형/컵 분류, 상자 2·3·4개 쌓기 중 작업을 선택한다.

수집 흐름은 **준비 5초 → START 1초 → 시연 → HOME 복귀 2초 유지 → 자동 저장**이다. 최소 시연 시간은 8초이고 최대 시간 제한은 없다. 실패 시연은 `f`로 폐기하고 10초 후 재시도하며, `q`로 종료하면 현재 미저장 시연을 폐기한다. 영상 누락·속도 저하가 감지된 시연도 저장하지 않으며, 저장·검증이 끝난 뒤 다음 시연을 시작한다.

저장 경로는 `D:\lerobot-2026\robot_datasets\tasks\<작업명>\dataset`이다. LeRobot 형식으로 수치 데이터는 `data/`의 Parquet, 영상은 `videos/`의 MP4, 작업 문장·에피소드 정보·통계는 `meta/`에 저장한다.

| 저장 항목 | 내용 |
|---|---|
| `observation.state` | Follower 6축 실제 관절 위치: 팔은 도, 그리퍼는 0–100 정규화 값 |
| `action` | 이동량 제한까지 적용한 Follower 최종 전달 명령 6축 |
| `research.leader_action_raw` | 전처리·이동량 제한 전 Leader 원본 6축 입력 |
| `observation.images.top`, `.side` | RGB 영상, H.264 / CRF 23 / ultrafast |
| `observation.images.top_depth` | 장치의 실제 depth scale로 mm 변환·반올림, 0–2000 mm로 제한 후 선형 12비트 + 무손실 HEVC 저장 |
| `research.motor_load_raw` | 매 프레임 Follower 6개 모터의 부호를 해석한 load 피드백 |
| `research.motor_current_raw` | 같은 프레임의 6개 모터 전류 피드백 원시값 |
| `research.motor_torque_limit_raw` | 같은 프레임에 읽은 6개 모터의 토크 제한 설정값 |
| 프레임 식별 정보 | timestamp, frame_index, episode_index, task_index로 수치·영상 구간 연결 |
| `research.capture_timing_s` | 에피소드 시작 기준 카메라 호스트 수신 시각, 관절·피드백 읽기 및 명령 전송 구간 |
| `research.camera_frame_numbers` | TOP RGB·depth 장치 번호와 SIDE 호스트 캡처 순번 |

모터 관절 순서는 각 항목의 `names`에 기록한다. load·current는 실제 N·m 토크나 컵에 가해지는 힘으로 환산하지 않는다. `research.*`는 기본 학습 입력에서 제외하며, 추후 전처리·모델 입력 구성을 추가해 활용할 수 있도록 보존한다.

작업별 폴더에 수집 설정·보정 파일 해시·실제 depth scale·저장 단위와 범위(`collection_manifest.json`), 에피소드별 기록(`sessions/`), 중단 복구용 사본을 별도로 관리한다. 새 수집 스키마는 버전 4로 기존 데이터와 혼합하지 않는다. 본 수집을 위해 `pick_doll`의 이전 데이터·복구 사본·수집 기록을 삭제했으며, 다음 수집부터 새로 시작한다.

D405 RGB·depth는 같은 버퍼 묶음으로 읽고, 카메라 반복·건너뛴 프레임을 검사한다. 품질 기준은 목표 30 FPS / 실제 평균 최소 27 FPS, 최대 프레임 간격 200 ms, 카메라 간 수신 시각 차이 50 ms, 전체 표본 시간 폭 150 ms, 프레임 나이 100 ms이다. 시각은 호스트 기준이며 하드웨어 동기화 보장은 아니다. LeRobot `timestamp`는 30 FPS 기준의 명목 시각이고 실제 시간은 별도 연구용 항목에 남긴다.

저장 후 수치 데이터·TOP RGB·TOP depth·SIDE RGB의 에피소드 구간 프레임 수를 실제 디코딩해 비교하고, 모든 depth의 양자화 코드와 정수 mm 복원이 완전히 일치하는지 검사한다. 범위 밖 픽셀 수도 기록한다. mm 반올림 이전 센서 raw 정밀도는 보존하지 않으며, depth 0은 invalid 값이다. 기준 미달 시 에피소드 전체를 정상 데이터에서 제외하고 같은 번호로 재시도한다. 저장 후 불합격 원본은 복구 격리 폴더에 보존하며, 결과는 `sessions/`에 기록한다.


## 2026-10-02 : 반복 폐기 원인 수정

실장비 수집이 약 22.2 FPS로 제한되어 27 FPS 기준 미달과 원본 프레임 건너뜀으로 시연이 반복 폐기되었다. 매 제어 주기마다 TOP·SIDE의 새 프레임을 각각 기다리던 방식을 최신 영상 재표본화로 바꿨다. 독립 카메라 속도 차이에 따른 반복·건너뜀은 통계로 남기고, 인코더 누락·저장 프레임 수 불일치·오래된 영상·실제 FPS·시간차·depth 복원 검사는 계속 유지한다.

Follower 위치·load·current·torque limit을 한 번에 읽도록 묶었다. 로봇을 움직이지 않은 실측에서 6개 모터를 4회 나눠 읽는 시간은 평균 4.01 ms, 묶어 읽기는 2.41 ms였다. 단계별 평균 처리 시간도 수집 기록에 남긴다. 저장된 시연이 없는 깨끗한 빈 데이터셋은 기존 폐기 기록과 이전 manifest를 보존하고 새 설정으로 갱신하며, 이미 저장된 시연이 있으면 설정 혼합을 막는다.

실제 TOP·SIDE 카메라와 Follower 피드백을 90주기 읽은 결과는 29.99 FPS, 최대 카메라 수신 시각 차이 24 ms, 품질 오류 0건이었다. SIDE 영상 반복 24회는 재표본화 통계로 기록됐다. 이 확인에는 로봇 이동 명령·화면 표시·영상 인코딩을 포함하지 않았으며 전체 시연 속도는 다음 수집 기록에서 확인한다. 결과는 `collection/reports/capture_read_profile.json`에 보관했다.

## 2026-10-02 : 카메라 시간 차이 허용 범위 조정

정상 속도 약 29.7 FPS·인코더 누락 0개인 시연도 최대 카메라 수신 시각 차이 52–57 ms 때문에 폐기되는 것을 확인했다. TOP–SIDE 시간 차이 허용값을 50 ms에서 100 ms로 완화했다. 실제 평균 최소 27 FPS, 영상 나이 100 ms, 표본 시간 폭 150 ms, 저장 프레임 개수·인코더 누락·depth 복원 검사는 유지한다. 품질 허용값만 바꿀 때는 이전 manifest를 보존하고 저장된 시연을 그대로 이어 수집할 수 있도록 수정했다.

## 2026-10-02 : 저장 대기 시간 개선

저장 후 이전 시연 전체를 다시 검사하던 중복 검사를 제거했다. 전체 검사는 수집 시작 시 유지하고, 저장 시에는 새 에피소드의 모든 수치 데이터·인덱스·시간·작업 문장·메타데이터 개수와 영상 프레임 수·depth 픽셀 일치를 검사한다. 새 에피소드 수치만 선택해 읽고 세 영상을 병렬로 검사하며, depth mm 변환은 동일 변환 결과표를 재사용한다. 저장·검사·재개 소요 시간은 앞으로 에피소드 기록의 `save_seconds`에 남긴다.

57개 시연 기준 기존 전체 검사만 11.22초 걸렸으며 이 대기를 제거했다. 새 검사로 마지막 514프레임 시연을 읽기 전용으로 검증한 시간은 4.94초, 오류 0건이었다. 이는 저장 전체 소요 시간이 아닌 검사 시간이다. 기존 데이터와 시연 메모 347개 파일의 SHA-256 비교 결과 변경 0개였다. 저장 형식·인코딩·수집 설정은 바꾸지 않아 기존 데이터에 이어 수집한다. 저장·복구·실제 HEVC depth 무손실 검사 등 41개 테스트가 통과했다. 로봇을 움직이는 전체 수집의 저장 대기는 다음 시연에서 기록된 시간으로 확인한다.

## 2026-10-08 : 웹캠 프레임 문제와 향후 수집 방침

### 현재 문제

SIDE 웹캠은 요청 30 FPS와 달리 실제로 약 22.2 FPS를 공급한다. 카메라 단독 측정과 USB 포트 변경 후에도 비슷해 수집 코드만의 병목으로 설명하기 어렵다. 장치·드라이버·영상 모드 중 정확한 제한 원인은 아직 확정하지 못했다.

인형 499개와 종이컵 102개 에피소드의 시간 기록에서 웹캠 공급률은 모두 약 22.23 FPS였다. 제어·저장 주기와의 차이로 SIDE 영상의 약 26%가 재사용됐으며, 이동과 그리퍼 동작 주변에서도 같은 현상이 있었다. PC 수신 시각부터 관절 읽기까지의 차이는 95%의 표본에서 약 47 ms 이내였고, 일부 에피소드에는 100 ms를 넘는 수집 간격이 있었다. 기록은 센서 촬영 시각이 아닌 PC 수신 시각이므로 실제 영상 지연 전체를 뜻하지 않는다.

10월 7일 진단에서 웹캠 노출을 변경한 뒤 노출 숫자만 복원하고 자동/수동 모드를 충분히 복원·검증하지 않았다. 이후 나타난 심한 과노출은 자동 노출을 켜서 복구했고, 재연결 후에도 정상 밝기를 확인했다. 위 인형·종이컵 데이터는 해당 노출 진단 전에 수집됐다.

현재 품질 검사는 전체 수집 FPS와 영상 나이 등을 확인하지만, 카메라별 지속적인 공급률 저하를 별도로 경고하지 않는다. 반복이 학습 성공률을 얼마나 낮추는지는 아직 검증하지 않았으며, 기존 데이터를 전량 폐기하거나 재수집해야 한다는 근거는 없다.

### 앞으로 할 일

- 기존 데이터와 30 Hz 수집 설정을 유지한다. 기존 데이터의 FPS 표시만 22로 바꾸지 않는다.
- 수집 전에 정상 밝기와 웹캠 실제 공급률을 확인하고, 복구된 자동 노출 상태를 유지한다. 추가 노출 시험은 원래 모드를 보존하고 영상까지 복원 검증할 수 있을 때만 한다.
- 수집 코드에 카메라별 신규 FPS·반복률·영상 나이·긴 수집 간격의 표시와 경고를 추가한다. 이는 아직 구현하지 않은 후속 작업이다.
- 현재 장비의 약 26% 반복만으로 시연을 자동 폐기하지 않는다. 평소보다 공급률이 떨어지거나 영상이 오래 멈춘 경우를 구분하고, 파지·놓기는 부드럽게 시연한다.
- 조금 천천히 부드럽게 움직이면 같은 영상을 재사용하는 짧은 시간 동안 로봇이 이동하는 거리가 줄어, 영상과 관절값의 차이를 완화할 수 있다. 특히 물체에 접근하는 마지막 구간, 그리퍼를 닫는 순간, 물체를 놓는 구간에서 급격한 움직임을 줄인다. 전체 시연을 지나치게 느리게 하거나 불필요한 정지 시간을 늘릴 필요는 없다. 이는 프레임 반복 자체를 없애는 해결책은 아니며, 학습 성능에 대한 실제 완화 효과는 추후 검증해야 한다.
- 수집 후 긴 지연과 반복이 큰 중요 동작 구간을 검토해 에피소드 사용 여부를 정한다. 파지 성능이 부족하면 별도 소규모 22 Hz 수집·학습·실행 비교를 거쳐 변경 여부를 결정한다.
