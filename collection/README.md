## 직접 실행

`collection/collect.py` 파일을 에디터의 실행 버튼으로 실행하세요. 바로가기는 필요 없습니다. 다른 Python으로 실행해도 프로젝트 가상환경으로 자동 전환합니다. 수집 시작 버튼은 정상 실행되는 python.exe를 사용하며 콘솔 창은 숨깁니다. Windows 보안 정책은 변경하지 않았습니다.

# 데이터 수집

**`수집 실행` 바로가기를 더블클릭하세요.**

또는 `collect.py`를 열고 편집기의 ▶ 실행 버튼을 누르면 같은 창이 열립니다. 프로젝트 가상환경은 자동으로 선택합니다.

1. 창에서 작업을 선택합니다: 인형 / 종이컵 / 분류 / 상자 2·3·4개 쌓기.
2. 로봇을 HOME 근처에 두고 **수집 시작**을 누릅니다.
3. **준비 5초 → START 화면 1초** 뒤 녹화가 시작됩니다.
4. HOME에서 벗어나 작업한 뒤 HOME으로 돌아와 **2초 유지하면 자동 저장**합니다. 최소 녹화 시간은 8초입니다.
5. 끝낼 때 **종료**를 누릅니다. 창을 닫아도 정리 완료 후 종료합니다.

실패한 시연은 자동 저장 조건에 도달하기 전에 **폐기** 버튼 또는 영상 창의 `f`를 누르세요. 바로 준비 화면으로 전환하고 **10초 후 같은 번호로 재시도**합니다. `q` 또는 종료 버튼은 현재 미저장 시연을 폐기하고 종료합니다. 이미 저장을 시작했다면 저장 완료를 기다린 뒤 종료합니다.

기존 auto_home과 같이 저장은 다음 준비 5초와 동시에 진행됩니다. 저장·검사가 더 오래 걸리면 완료될 때까지 기다린 뒤 START 1초로 넘어갑니다. 준비 중에는 검은 배경의 숫자 카운트다운, START 때는 큰 START 문구를 표시합니다. 저장 중에도 카메라 화면 갱신과 텔레오퍼레이션을 유지합니다. 데이터 사본 준비가 필요하면 START 전에 잠시 지연될 수 있습니다.

영상 누락·속도 저하가 감지된 시연은 실패 표시를 유지하고 HOME 복귀 또는 수동 폐기 시 폐기하며 10초 후 재시도합니다. 에피소드 최대 시간 제한은 없습니다. 수집 창을 여는 것만으로 로봇은 연결되지 않습니다. ‘수집 시작’을 누르면 장비에 연결하고 텔레오퍼레이션이 시작됩니다.

## 저장과 재개

원본은 `D:\lerobot-2026\robot_datasets\tasks\작업이름\dataset`에 저장합니다. 창에서 저장 경로와 시연 수를 확인할 수 있습니다. 같은 작업으로 다시 시작하면 다음 시연부터 이어집니다.

각 작업의 자연어 문장, TOP/SIDE RGB, TOP depth, 관절 상태와 action을 기존 LeRobot 형식으로 저장합니다. `action`은 이동량 제한까지 적용한 Follower 최종 전달 명령이고, Leader 원본은 `research.leader_action_raw`에 따로 저장합니다. 데이터는 추후 ACT와 SmolVLA에서 재사용할 수 있습니다. 개별 데이터셋의 로컬 `task_index=0`은 정상이며, 작업 문장으로 서로 구분합니다.

녹화 프레임마다 follower 6개 모터에서 `Present_Load`, `Present_Current`, `Torque_Limit`을 읽어 `research.motor_load_raw`, `research.motor_current_raw`, `research.motor_torque_limit_raw`에 저장합니다. 관절 순서는 각 항목의 `names`에 기록됩니다. load는 부호를 해석한 모터 출력 피드백이고 current는 원시 전류 피드백이며, torque limit은 설정된 제한값입니다. 실제 N·m 토크 측정값으로 환산하지 않습니다. 통신 읽기에 실패하면 오류를 보고하며 가짜 0으로 대체하지 않습니다. 추가 읽기는 녹화 중에만 수행합니다.

연구용 항목은 기존 `observation.state`와 분리되어 기본 정책 입력에서 제외됩니다. 추후 학습에 사용하려면 별도 입력 변환과 실행 시 동일 피드백 읽기를 추가해야 합니다. 새 수집 스키마는 버전 4이며 기존 스키마와 섞어 이어 수집하지 않습니다.

D405의 실제 `depth_scale`로 raw 값을 mm로 변환하고 0–2000 mm 범위로 제한합니다. 범위 밖 픽셀 수를 기록하며, 0은 유효한 거리 측정값이 아니라 센서의 invalid 값입니다. 실제 scale·저장 단위·범위·선형 12비트 양자화 설정은 manifest에 기록합니다. HEVC 무손실 저장 후 모든 depth 프레임의 양자화 코드와 변환·범위 제한 후 정수 mm 값을 디코딩 결과와 각각 비교합니다. 센서 원본의 0.1 mm 정밀도와 범위 밖 값까지 보존하는 형식은 아닙니다.

D405 RGB·depth와 수신 시각·프레임 번호는 한 잠금 안에서 함께 읽습니다. `research.capture_timing_s`에는 에피소드 시작 기준의 카메라 호스트 수신 시각, 관절·모터 피드백 읽기 구간, 명령 전송 구간을 저장합니다. `research.camera_frame_numbers`에는 TOP RGB·depth의 장치 프레임 번호와 SIDE의 호스트 캡처 순번을 저장합니다. SIDE 순번은 Webcam 장치 자체의 번호가 아니며 카메라 간 하드웨어 동기화를 의미하지 않습니다.

품질 기준은 목표 30 FPS, 실제 평균 최소 27 FPS, 프레임 간격 최대 200 ms, TOP–SIDE 수신 시각 차이 최대 100 ms, 전체 표본 시간 폭 최대 150 ms, 카메라 프레임 나이 최대 100 ms입니다. 카메라는 제어 루프를 기다리게 하지 않고 매 시점의 최신 영상을 사용합니다. 서로 다른 카메라 속도에 따른 반복·건너뛴 원본 프레임은 재표본화 통계로 기록하며 그 자체로 폐기하지 않습니다. 인코더 누락, 오래된 영상, FPS·시간차 기준 위반은 실패 처리합니다. 관절 위치·load·current·torque limit은 주소 48–70의 단일 통신으로 함께 읽습니다. 저장 완료 전에 수치 데이터와 세 영상의 해당 에피소드 구간을 실제 디코딩해 프레임 수를 비교합니다. FPS·개수·depth 복원 검사에 실패하면 해당 에피소드를 정상 데이터셋에서 제외하고 같은 번호로 재시도하며, 저장 후 불합격 원본은 복구 격리 폴더에 보존합니다. `sessions/`에 성공·폐기 시연의 FPS, 각 프레임 수, 누락·시간차·depth 검사 결과를 기록합니다. 저장 중단으로 품질 검사가 끝나지 않았으면 재개 시 이전 정상 데이터로 복구합니다.

시작할 때 전체 데이터 무결성을 검사합니다. 저장 후에는 새 에피소드의 수치·인덱스·시간·작업 문장·전체 개수와 세 영상의 프레임 수 및 모든 depth 픽셀을 검사합니다. 수치 읽기는 새 에피소드만 선택하고 영상 검사는 병렬로 실행해 이전 시연 전체를 매번 다시 검사하는 대기를 없앴습니다. `sessions/episode_*.json`의 `save_seconds`에 저장 마무리·검사·재개와 전체 소요 시간을 기록합니다. 기존 파일과 인코딩·스키마는 유지합니다. 영상 누락과 느린 수집 감지, 저장 공간 확인, 장비 중복 실행 방지도 유지합니다. 중단된 저장이 있으면 시작 버튼에서 복구를 시도하며, 실패 상태 원본은 별도 폴더에 보존합니다. 복구 실패 시 수집을 시작하지 않고 오류를 표시합니다. 작업 문장·보정값·장비 설정이 달라지면 기존 데이터에 섞어 저장하지 않습니다.

기존 `episode_sample_dataset/auto_home_collection/auto_home_record.py`의 검증된 장비·인코딩 도우미를 계속 사용하므로 해당 파일은 유지합니다. 기존 수집 프로그램과 새 수집 창에서 동시에 수집하지 마세요.
# RGB 무손실 저장

중단 복구는 이미 검증한 전체 영상의 재디코딩을 하지 않고, 원본을 보존한 채
수치·메타데이터와 영상 경로·크기를 확인해 마지막 정상 사본을 복원합니다.
마지막 변경 가능 영상은 별도 복사본을 사용하고, 이전 불변 영상은 같은 디스크의
하드 링크로 재사용해 전체 데이터 복사를 피합니다. 복구 진행 상황을 표시하며
종료 요청은 단계 사이에서 처리합니다. 종료 후 검사 중에도 종료 버튼으로 중단할
수 있고, 남은 검사 기록은 다음 실행에 이어집니다.

저장 시에는 수치 데이터·인덱스·시간·작업 문장과 모든 영상 패킷의 프레임
순서를 확인합니다. 각 영상은 처음·끝과 중간을 고르게 포함한 10개 프레임만
디코딩하고, 선택한 깊이 프레임은 모든 픽셀의 코드와 mm 값을 원본과 비교합니다.
이 단계는 미검사 프레임의 손상을 놓칠 수 있으며 전체 검증 완료로 표시하지 않습니다.
종료 시 장비를 먼저 해제한 뒤 영상 패킷의 프레임 순서를 확인하고, 각 영상은
처음·끝을 포함해 최대 50개 프레임을 고르게 검사합니다 (`exit_video_samples: 50`).
깊이는 선택한 프레임의 모든 픽셀을 비교하며 전체 깊이 검증과 구분해 기록합니다.
전체 비교용 원본 해시는 `verification_pending`에 보존합니다. 강제 종료로 남은
검사는 다음 수집 시작 전에 재개합니다. 전체 검사 실패 시 수집 재개를 차단하고
실패한 시연 번호를 기록합니다. 학습에는 전체 검사 통과를 확인한 데이터를 사용하세요.
`settings.json`의 `verification.video_samples`로 표본 수를 지정합니다.

각 시연의 인코더 초기화는 녹화 전 준비 단계에서 마칩니다. GPU 초기화 지연이
첫 두 프레임 사이에 들어가 같은 시연이 반복 폐기되는 문제를 방지합니다.
초기화에는 실제 녹화 프레임이나 더미 프레임을 저장하지 않으며, START 1초는
초기화가 끝난 뒤부터 표시합니다. 녹화 중 프레임 간격 기준은 유지합니다.

저장 직후 카메라 버퍼가 오래되었으면 즉시 종료하지 않고 기존 200 ms 대기
범위 안에서 새 프레임을 기다립니다. 오래된 영상은 녹화에 넣지 않습니다.
인코더에는 각 2개 스레드를 지정해 카메라 처리에 CPU 여유를 남깁니다.
계속 갱신되지 않으면 TOP/SIDE 이름과 버퍼 나이가 포함된 오류로 종료합니다.

수집 시에는 카메라 버퍼 나이를 품질 기준 100 ms보다 짧은 80 ms로 제한하여
모터 읽기·명령 전송에 20 ms 여유를 둡니다. SIDE 갱신을 기다리는 동안 TOP이
오래되었다면 두 카메라를 다시 확인합니다. 새 버퍼 대기는 총 200 ms로 제한합니다.
30 FPS 제어 주기는 절대 시각을 기준으로 기다리며, 바쁜 반복 대기 대신
카메라·인코더 스레드가 실행될 수 있도록 잠듭니다. 긴 지연 뒤에는 밀린 프레임을
한꺼번에 만들지 않습니다. 미리보기만 최대 15 FPS이고 녹화 목표는 30 FPS입니다.
세션 품질 기록에 카메라별 최대 버퍼 나이도 남깁니다. 품질 허용 기준은 유지합니다.

`settings.json`의 `rgb_encoder`는 RGB TOP/SIDE를 GPU `h264_nvenc`,
`tune=lossless`, GBRP 입력으로 무손실 압축합니다. 파일 경로와 MP4 확장자는 유지합니다.
CPU `libx264rgb`로 저장된 기존 영상도 H.264 GBRP이므로 같은 데이터셋에 이어 저장합니다.
백엔드 전환 시 기존 manifest는 보존하고, 각 새 시연 기록에 실제 RGB 인코더 설정을 남깁니다.
새 데이터셋을 다시 열 때 GPU 무손실 설정도 복원합니다.
깊이는 HEVC 무손실과 기존 12비트·mm 표현을 유지하며,
`depth_encoder_preset=ultrafast`로 압축 속도를 우선합니다. 실제 깊이 영상 120프레임
비교에서 fast 9.49초 → ultrafast 2.79초, 파일 크기는 약 35% 증가했고
모든 프레임의 깊이 코드가 일치했습니다. 측정 보고서는
`collection/reports/depth_encoding_profile.json`입니다.

시연 저장 후에는 Parquet 파일을 닫아 즉시 읽을 수 있도록 하되 수집 객체를 재사용합니다.
다음 시연은 새 데이터·메타데이터 파일에 기록하여 기존 파일을 덮어쓰지 않습니다.
매 저장 때 과거 모든 시연의 메타데이터를 재로딩하던 대기를 제거합니다.
영상만 사용하는 수집에서는 불필요한 이미지 바이트 변환과 PNG 저장 스레드도 생략합니다.
검사에서는 필요한 메타데이터 열과 해당 시연의 숫자 파일을 읽습니다.
검사 항목과 표본 수는 유지하고, 저장·검사·총 시간을 화면 및 세션 기록에 남깁니다.
실제 장비의 30 FPS 및 전체 저장 대기는 새 수집 실행에서 확인해야 합니다.

기존 원본 수집 영상 변환: 프로젝트에서
`.\.venv\Scripts\python.exe scripts\migrate_rgb_lossless.py`를 실행합니다.
